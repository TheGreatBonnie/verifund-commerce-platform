# Conversation History — Design Spec

**Date:** 2026-11-01
**Status:** Approved
**Scope:** Durable, per-user conversation history across CopilotKit transcript, Google ADK orchestrator sessions, and LangGraph buyer/verifund checkpoints.

---

## 1. What the docs require

CopilotKit's thread-lifecycle docs describe three layers, and this repo has all three:

| Layer | What it stores | Current state |
|---|---|---|
| CopilotKit thread | AG-UI event history: messages, tool calls, state, replay | Runtime can be Intelligence-backed, but no key is set; falls back to `InMemoryAgentRunner`. No explicit `threadId` on the chat. |
| Framework session/checkpoint | The agent's own model context and graph state | `orchestrator_agent` is Google ADK, in-memory, 1-hour TTL. `buyer_agent` and `verifund_agent` are LangGraph with `AsyncSqliteSaver`. |
| App/business history | Runs, trace events, agreements, orders | Durable in buyer/control-plane APIs; rendered at `/runs`. Not the chat transcript. |

The docs' non-negotiables:
- Replay requires a **server-side store**. Passing `threadId` alone is not enough.
- Mount-time hydration requires an **explicit `threadId`** on the chat.
- `setActiveThreadId` / `startNewThread` **no-op** when `threadId` is prop-controlled.
- `useThreads` needs the runtime to advertise thread endpoints. With Intelligence, the full contract (list, replay, rename, archive, delete, realtime, per-user scoping) is available.

## 2. The core problem

Three unrelated IDs are currently uncorrelated:

```
CopilotKit threadId (route UUID)
  ├─ AG-UI event store       → not persisted today
  ├─ ADK session ID          → generated internally, 1-hour TTL, lost on restart
  └─ A2A contextId           → generated per buyer/seller call
       ├─ buyer LangGraph thread_id   = A2A context_id
       └─ verifund LangGraph thread_id = A2A task_id
```

Plus a latent bug: the buyer executor uses `thread_id = context_id` on a fresh run but `thread_id = payload["task_id"]` on approval/seller-result resumes. Today `context_id == task_id` (no explicit contextId is sent), so it works. The moment we propagate a real threadId, it breaks.

## 3. Target ID model

**One `threadId` is the identity of a whole conversation (and, by invariant, one procurement run).**

| Component | ID used | How it gets there |
|---|---|---|
| Browser route | `threadId` (UUID) | Minted by the console before navigation |
| CopilotKit thread | `threadId` | Passed as prop to `CopilotChat` |
| AG-UI event store (Intelligence) | `threadId` | Run request carries it |
| ADK orchestrator session | `threadId` | `use_thread_id_as_session_id=True` + `DatabaseSessionService` |
| A2A `contextId` (buyer, sellers, verifund) | `threadId` | Middleware patch + Python tools reading `tool_context.session.id` |
| Buyer LangGraph checkpoint | `threadId` | `thread_id = context_id` (already) |
| Buyer business `run_id` | `threadId` | `run_id = config["configurable"]["thread_id"]` (already) |
| Verifund LangGraph checkpoint | `threadId` | `_config(context_id)` instead of `_config(task_id)` |
| A2A task IDs | per-message UUID | Generated by A2A server; correlation via `contextId` |

**Invariant: one thread = one procurement run.** Starting a new run always mints a new thread. Buyer/verifund graphs model a single transaction lifecycle (interrupts, award, order); reusing one graph thread across two runs would resume a finished graph and silently return stale state. The buyer executor returns a structured `thread_in_use` failure if a fresh brief arrives on a non-empty checkpoint.

## 4. Layer 1 — CopilotKit Intelligence

### Runtime (`apps/console/app/api/copilotkit/[[...slug]]/route.ts`)

- Keep the existing conditional block; set `CPK_INTELLIGENCE_API_KEY` to activate it.
- `identifyUser: async () => ({ id: "demo-user", name: "Demo User" })` for the hackathon. Stable, demo-only. The id must exist in the Intelligence project (create it in the dashboard as a setup step).
- Keep `agents` as the `MarketMeshA2AMiddlewareAgent` instance.

### Thread endpoints and `useThreads`

- Intelligence provides the full contract: `threads/list`, `threads/messages`, `threads/update`, `threads/archive`, `threads/delete`, realtime metadata.
- The headless panel gates on runtime capability, not a build-time flag:
  ```ts
  const canList = copilotkit.threadEndpoints?.list === true;
  const canMutate = copilotkit.threadEndpoints?.mutations === true;
  const threads = useThreads({ agentId: "marketmesh_orchestrator", enabled: canList });
  ```
- `NEXT_PUBLIC_COPILOTKIT_THREADS_ENABLED` stays for the cosmetic app frame and settings page; it is not the source of truth for the panel.

### New-thread minting

- Never call `startNewThread()` when `threadId` is prop-controlled (it no-ops).
- "New conversation": mint `crypto.randomUUID()` and `router.push('/runs/' + uuid)`. The chat connects to an empty thread; Intelligence creates the row on the first run.

### Hydration

- `<CopilotChat agentId="marketmesh_orchestrator" threadId={threadId} />` passes the explicit prop. On mount, `CopilotChat` sets `agent.threadId = resolvedThreadId` and calls `copilotkit.connectAgent`, which clears client state on a fresh restore and replays persisted events (messages, tool calls, state).

## 5. Layer 2 — ADK durable sessions

### `apps/orchestrator_agent/orchestrator_agent/server.py`

```python
from google.adk.sessions import DatabaseSessionService
from orchestrator_agent.settings import Settings

def create_app(settings: Settings | None = None) -> FastAPI:
    settings = settings or Settings()
    agent = build_agent(settings)
    session_service = DatabaseSessionService(settings.session_db_url)
    adk_agent = ADKAgent(
        adk_agent=agent,
        app_name="marketmesh_orchestrator",
        user_id="demo_user",
        session_timeout_seconds=30 * 24 * 3600,  # effectively never (cleanup disabled)
        use_in_memory_services=True,
        session_service=session_service,
        use_thread_id_as_session_id=True,
    )
    ...
```

- `use_in_memory_services=True` keeps artifact/memory/credential services in memory (acceptable for the demo).
- `delete_session_on_cleanup=False` is set via a `SessionManager` constructed with the session service, or by overriding the default. Concretely: pass `session_service=...` and set `delete_session_on_cleanup=False` through the manager. Since `ADKAgent` accepts `session_manager` too, construct:
  ```python
  from ag_ui_adk import SessionManager
  session_manager = SessionManager(
      session_service=session_service,
      memory_service=None,
      session_timeout_seconds=30 * 24 * 3600,
      delete_session_on_cleanup=False,
      save_session_to_memory_on_cleanup=False,
      use_thread_id_as_session_id=True,
  )
  ADKAgent(..., session_manager=session_manager, use_in_memory_services=True)
  ```
  If `SessionManager` requires a memory service, pass `InMemoryMemoryService()`.
- `DatabaseSessionService` uses SQLAlchemy async; the URL must use an async driver: `sqlite+aiosqlite:///./data/orchestrator_sessions.db`.

### Settings

Add to `Settings`:
```python
session_db_url: str = Field(
    default="sqlite+aiosqlite:///./data/orchestrator_sessions.db",
    validation_alias=AliasChoices("ORCHESTRATOR_SESSION_DB_URL"),
)
```
and `Path(...).parent.mkdir(parents=True, exist_ok=True)` in `__main__.py` (mirror buyer/verifund).

### Result

The ADK session id equals the CopilotKit threadId. The orchestrator's model context (tool results, reasoning) survives restarts. Python tools can read the threadId via `tool_context.session.id`.

## 6. Layer 3 — LangGraph continuity + A2A correlation

### 6.1 A2A middleware patch

`@ag-ui/a2a-middleware@0.0.6` is the latest and does not send `contextId`. Patch it via `pnpm patch` (recorded in `pnpm-lock.yaml`):

1. `sendMessageToA2AAgent(agentName, task, contextId?)` adds `contextId` to the A2A message:
   ```js
   client.sendMessage({ message: { kind: "message", messageId, role: "agent", parts: [{ text: task, kind: "text" }], ...(contextId ? { contextId } : {}) } })
   ```
2. In `wrapStream`, capture `const threadId = runInput?.threadId;` and pass it as the third argument.

The patch is small, concurrency-safe (threadId is captured per-run, not stored on the shared instance), and is the only way to put `contextId` on the initial buyer message. The local `MarketMeshA2AMiddlewareAgent` subclass in `route.ts` needs no change; it inherits the patched method.

### 6.2 Buyer executor (`apps/buyer_agent/buyer_agent/executor.py`)

Normalize the graph thread key to `context_id` on every path (today it switches to `payload["task_id"]` / `review_request.buyer_context_id`):

```python
thread_id = context.context_id or str(payload.get("task_id") or task_id)
...
config = {"configurable": {"thread_id": thread_id, "services": ..., "planner": ...}}
```
Remove the three reassignments that override `thread_id` from `payload["task_id"]` / `buyer_context_id`.

Add a guard for the one-run-per-thread invariant:
```python
snapshot = await self.graph.aget_state(config)
if snapshot.values and (snapshot.values.get("stage") not in (None, "new")):
    return self._fail(..., reason="thread_in_use",
        message="This conversation already contains a run. Start a new conversation for a new purchase.")
```

### 6.3 Verifund service (`apps/verifund_agent/verifund_agent/service.py`)

```python
def _config(self, context_id: str) -> dict[str, Any]:
    return {"configurable": {"thread_id": context_id, "buyer": self.buyer}}
```

Update every call site (`handle`, `resume`, `aget_state` snapshots, receipt, status) to pass `context_id` instead of `task_id`. `get_agreement(task_id)` becomes `get_agreement(context_id)`.

Make the orchestrator's `verifund_create_agreement` send `context_id=buyer_context_id` (which is the threadId, carried in the buyer response) on the first `_exchange`, so verifund's A2A context matches.

Add a guard in `_agreement_create`: if an existing checkpoint has a different `run_id`, fail with `thread_in_use`.

### 6.4 Orchestrator Python tools (`agent.py`)

Use the ADK session id (== threadId) instead of hoping the LLM passes `context_id`:

```python
from google.adk.tools import ToolContext

async def mediate_seller_call(
    buyer_task_id: str, ..., tool_context: ToolContext,
) -> dict:
    thread_id = tool_context.session.id
    ...
    # resume the buyer with context_id=thread_id
    # seller call uses context_id=thread_id
```

`tool_context` is a special parameter injected by ADK and excluded from the LLM tool schema.

### 6.5 One-run-per-thread guard (summary)

- Buyer: fresh brief on a non-empty checkpoint → `thread_in_use`.
- Verifund: `agreement_create` on a checkpoint with a different `run_id` → `thread_in_use`.
- UI: "New run" always mints a new thread; the orchestrator relays the guard error verbatim if a second purchase is attempted in one thread.

## 7. UI — headless history panel in the run detail

### Placement

A `ConversationHistory` component rendered at the top of `.mm-chat-rail` in `RunDetail` (inside `RunDetailWorkspace` or above it). Collapsible. Follows `mm-*` styling. Hidden when `!canList`.

### `useThreads` usage

```tsx
const { copilotkit } = useCopilotKit();
const canList = copilotkit.threadEndpoints?.list === true;
const canMutate = copilotkit.threadEndpoints?.mutations === true;
const {
  threads, isLoading, listError, isMutating,
  renameThread, archiveThread, unarchiveThread, deleteThread,
  fetchMoreThreads, hasMoreThreads, isFetchingMoreThreads, refetchThreads,
} = useThreads({ agentId: "marketmesh_orchestrator", enabled: canList, limit: 20 });
```

### Interactions

- Row click → `router.push('/runs/' + thread.id)` (always the full workspace route).
- Active row highlighted by matching the route's `threadId`.
- Rename: inline input → `renameThread(id, name)`.
- Archive / delete: confirm dialog → `archiveThread` / `deleteThread`. If the active thread is archived or deleted, navigate to `/runs`.
- Archived toggle → `includeArchived` input, refetches.
- Pagination → `limit: 20` + `fetchMoreThreads`.
- "New conversation" → mint UUID, navigate to `/runs/{uuid}` (no pending brief).
- Error → `listError?.message` + Retry button (`refetchThreads`).
- Mutations gated on `canMutate` (hide buttons otherwise, but listing still works).
- Empty state: "No conversations yet. Start a run."

### Accessibility

`nav aria-label="Conversation history"`, `aria-current` on the active row, focusable rows, confirm dialogs with `role="dialog"` and `aria-modal`, keyboard activation.

## 8. Route and chat wiring

### Routes

`/runs/{threadId}` and `/agents/{threadId}` both render `RunDetail`. The route param is the `threadId`. No change to the routes themselves.

### Chat (`apps/console/features/chat/chat.tsx`)

Add an optional `threadId` prop and forward it to `CopilotChat`:
```tsx
<CopilotChat agentId="marketmesh_orchestrator" threadId={threadId} ... />
```

### RunDetail (`apps/console/features/deal-room/run-detail.tsx`)

- Pass `threadId={runId}` to `<Chat>`.
- Render `<ConversationHistory>` in the chat rail.
- `handleNewRun` keeps minting a UUID and navigating; no manual `resetForRun` needed beyond what the component remount handles.

### `useRunDetail` (`apps/console/features/deal-room/hooks/use-run-detail.ts`)

- Remove `agent.threadId = routeRunId` effects (the chat sets it; redundant).
- Remove `agent.setMessages([])` / `agent.setState({})` from `startRun` (connect handles fresh-thread reset).
- Pending-brief auto-start waits for replay to settle:
  ```ts
  useEffect(() => {
    if (!isReady) return;
    let pendingBrief = ...sessionStorage...;
    if (!pendingBrief) return;
    let cancelled = false;
    (async () => {
      await copilotkit.connectAgent({ agent });   // settles fresh-thread reset
      if (cancelled) return;
      // now startRun
    })();
    return () => { cancelled = true; };
  }, [isReady, threadId]);
  ```
- Keep `agent.threadId = threadId` in a layout effect for the imperative run path.

### `startRun`

Keep `copilotkit.runAgent({ agent })`; do not clear messages. On a fresh thread there is nothing to clear; on an existing thread the new user message appends.

## 9. End-to-end walkthrough

1. `/` → "Start Shopping" mints `T`, stores brief, navigates to `/runs/T`.
2. `RunDetail` mounts; `CopilotChat` sets `agent.threadId=T`, connects (empty replay); pending-brief effect awaits connect, then `runAgent`.
3. Runtime run request carries `threadId=T`; Intelligence records AG-UI events under `T` for `marketmesh_orchestrator` / `demo-user`.
4. A2A middleware tool call → buyer message with `contextId=T`.
5. Buyer: `context_id=T`, `thread_id=T`, checkpoint under T, run row `run_id=T`.
6. Orchestrator resumes buyer with `context_id=T` (ToolContext); verifund sends `context_id=T`; verifund checkpoint under T; A2A tasks under context T.
7. ADK session id = T in `orchestrator_sessions.db`.
8. `useRun(T)` fetches `/api/runs/T` → row appears; trace works.
9. Reload `/runs/T`: Intelligence replays messages/tool cards/state; ADK session restored; buyer/verifund checkpoints intact; `useRun` fetches the row.
10. History panel lists T with an auto-generated name; clicking T′ navigates and the chat replays T′.

## 10. Failure modes and limits

- **No Intelligence key:** `canList=false`; panel hidden. Local `InMemoryAgentRunner` still replays within the process lifetime. ADK/LangGraph remain durable. Documented as degraded mode.
- **Unknown `demo-user`:** list/mutations fail; `listError` surfaces. Setup step: create the user in the Intelligence dashboard.
- **Intelligence WS down:** list works over REST; realtime updates lag; `refetchThreads` recovers.
- **Runtime restart:** Intelligence replays transcript; ADK session persisted; LangGraph persisted; A2A tasks persisted. Full recovery.
- **Orchestrator DB unwritable:** startup or session calls fail; surface via `/ready` and logs.
- **Shared demo user:** all browsers share one thread scope (intended for the demo).
- **`threads/events` and `threads/state` are not user-scoped** (Intelligence design). They back the Inspector only; do not expose the Inspector in production. If exposed, add an `onBeforeHandler` ownership check.
- **Middleware upgrade:** the pnpm patch is version-pinned; re-verify on upgrade. Add a test that asserts the buyer's `run_id` equals the route `threadId` (end-to-end consequence).
- **One-run-per-thread:** enforced by the buyer/verifund guards; a second purchase in one thread returns a structured `thread_in_use` error that the orchestrator relays.

## 13. Out of scope

- Migrating the orchestrator from ADK to LangGraph (decided: keep ADK).
- Importing pre-existing buyer/LangGraph conversations into Intelligence (future conversations only).
- Multi-user auth (single `demo-user`).
- Custom durable `AgentRunner` (Intelligence is used).
- Real-time collaboration beyond Intelligence's realtime metadata.

## 14. Decisions recorded

1. Keep the Google ADK orchestrator; persist its sessions with `DatabaseSessionService`; propagate one threadId.
2. CopilotKit Intelligence for durable AG-UI event history and the full `useThreads` contract.
3. Single shared `demo-user` identity for the hackathon.
4. Future conversations only; no import of existing runs.
5. Headless `useThreads` panel inside the run detail (not the global sidebar or the prebuilt drawer).
6. `/runs/{threadId}` (and `/agents/{threadId}`) is the single source of thread identity; explicit `threadId` prop on `CopilotChat`.
7. ADK sessions use `DatabaseSessionService` with `use_thread_id_as_session_id=True`; other ADK services stay in-memory.
8. Propagate the CopilotKit `threadId` as A2A `contextId`. Buyer already uses `context_id` as the LangGraph thread id; verifund switches from `task_id` to `context_id`.
9. **One thread = one procurement run.** LangGraph checkpoints are keyed by the thread id; guards prevent a second run in the same thread.
10. A2A middleware patched via `pnpm patch` to send `contextId`.
11. Headless panel gated on runtime `threadEndpoints.list`, not a build-time flag.
